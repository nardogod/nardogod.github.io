Intigriti Challenge 1126 · Write-up

The “internal-only” protocol that wasn’t: HTTP bridge → signature bypass → RCE (Intigriti Challenge 1126)

Leonardo Gomes · github.com/nardogod

Intigriti’s November CTF shipped a custom binary protocol that was meant to stay on localhost. An HTTP bridge put it on the public internet.

Recon. I pulled the superfastserver binary and reversed it. Two things stood out: a custom protocol bound to 127.0.0.1, and a POST /custom_protocol endpoint that opened a socket to that local service, forwarded the request body verbatim, and returned the reply. The port was firewalled from outside. Over HTTPS you still reached it.

The protocol. Authenticate, then send frames: code, data, signature, execute. The design ran a signed interpreter over a program, with RSA-2048 over SHA-256(code ‖ data).

The bug (two layers).

  1. The bridge turned a localhost-only service into an unauthenticated remote one.
  2. The signature covered the first data block. Execution used the last. Same length, second block attacker-controlled — valid signature, wrong code runs.

The interpreter’s memory tape sat next to the flag in thread-local storage. Walk the tape, print the flag. Unauthenticated remote code execution plus a memory read, over a single HTTPS POST.

Impact. Anyone on the internet could reach the “internal” protocol, bypass the signature check, and read adjacent process memory — including the flag.

Takeaways. Relay endpoints without auth or network lock-down are a foothold. Signature checks only cover the bytes you hash. Mapping the HTTP surface against the binary is how you catch services that look internal and aren’t.

Result. Accepted as Medium on Intigriti. Unlocked Bronze Finder, Impact Maker, and The Web Slinger. I’m finishing a security specialization at a Brazilian university and working through challenges like this — plus TryHackMe and TCM Security — while looking for junior SOC / GRC / IAM roles.

Thanks Intigriti. Write-up contest entry — feedback welcome.
